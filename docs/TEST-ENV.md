# テスト環境（iPhone の Safari で速さを確かめる）

今の公開ページはそのままにして、別の場所 **`/test/`** に、同じアプリを「クロスオリジン分離」して開けるようにした。
分離したページでは、音声認識（ONNX Runtime）が複数のスレッドを使える。

| | 今の公開ページ `/` | テスト環境 `/test/` |
|---|---|---|
| 中身（アプリのファイル） | 同じ | 同じ |
| COOP・COEP の見出し | なし | あり（`functions/test/[[path]].js` が付ける） |
| 音声認識のスレッド | 1 | 自動（端末のコア数から1つ残して最大4）。`?asrThreads=1` などで指定もできる |
| 計測の表示 | なし | 画面の上に出る |

## しくみ

- `functions/test/[[path]].js`（Cloudflare Pages Functions・無料の範囲）: `/test/〜` を、同じファイル（`/〜`）に見出しを付けて返す
- `_routes.json`: Functions を通すのは `/test` と `/test/*` だけ（ほかのページは今までどおり静的なファイル）
- `js/reazon-worker.js`: 分離されたページでだけ複数スレッドを使う。分離されていなければ1スレッド（今までと同じ）。
  複数スレッドで準備に失敗したら、1スレッドでやり直す
- `js/testpanel.js`: テスト環境だけで出す計測の表示
- `vendor/ort/`: ONNX Runtime 1.22.0 の控え（`?ort=local` のときだけ使う。CDN から読めない場合に比べるため）

## 元に戻す方法

`functions/`・`_routes.json` を消すと、テスト環境はなくなる（公開ページには影響しない）。
`js/testpanel.js`・`vendor/ort/` は、テスト環境でしか使わない。

## 分かっていること（PC の Chromium で確認）

- 分離したページで、外部のファイル（ONNX Runtime・音声認識のモデル・字幕の辞書）は読み込めた（試験では手元に置いた同じファイル。
  本当の CDN・Hugging Face の見出しは、テスト環境の「外部ファイルの読み込みを確かめる」で確かめる）
- 音声認識は 1スレッド 15.3秒 → 4スレッド 5.9〜6.6秒（120秒の音声）。メモリは増えなかった
- 文字起こしの文字は同じ。ただし複数スレッドでは、計算の順番が変わるため、一部の文字の時刻が 0.04〜0.08秒ずれることがある
- WebKit（Linux）では SharedArrayBuffer が使えず、複数スレッドは試せていない（iPhone の Safari で確かめる）

## iPhone での確かめ方

公開ページの住所の後ろに `/test/` を付けて開く（例: `https://claude-amity-video-editing-i.amity-ai-projects.pages.dev/test/`）。

1. 上のオレンジ色の枠（テスト環境）の「クロスオリジン分離」が「はい」、SharedArrayBuffer が「あり」になっているかを見る
2. 「外部ファイルの読み込みを確かめる」を押し、6つすべてに ○ が付くかを見る
3. いつもどおり動画を選び、「カットのみ（試作）」で「自動編集を開始」→ 書き出しまで進める
4. 枠の中の「音声認識」「動画の書き出し」「高速書き出し」「エラー」を見る
5. 「音声認識の速さを比べる（1・2・4スレッド）」を押す（解析した音声の最初の90秒で、1・2・4スレッドを順に測る。数分かかる。画面を離れない）
6. 「結果をコピー」を押して、その文を送る

うまくいかないとき:

- 2 で ONNX Runtime（CDN）が × → `/test/?ort=local` で開き直して 3〜6 をやり直す
- 途中で Safari が落ちる・止まる → `/test/?asrThreads=1` で開き直して同じ動画で試し、落ちるかどうかを比べる
- 今の公開ページ（`/test/` を付けない住所）は、今までどおり使える
