# Amity AI動画編集 改善計画（2026年10月）

目標: iPhoneで撮影した美容師のカット解説動画を、**少ない手直しでYouTubeに投稿できる品質**にする。
ショート（縦9:16・約60秒）とロング（横16:9・約10分）の両方で、

撮影 → タイトル・内容・流れを入力 → 完成時間・編集スタイルを選ぶ → AIが自動編集 →
字幕・カット・ズーム・BGMを確認 → MP4をiPhoneに保存

までを実現する。

## 現状の調査結果（v0.6 時点）

| 項目 | 現状 | 主な問題 |
| --- | --- | --- |
| 自動カット | 50msごとの音量で発話を検出。0.3秒以上の無音は前後0.1秒だけ残して削除 | 文と文の間がほぼ0.2秒に詰まり早口に聞こえる／一方で4秒以上の間が残る所もある。Whisperの時刻で区間を切り落とすため語尾が欠ける。つなぎ目ごとに音を一度0にするため「プツッ」と途切れる。ハサミの音を「声」と見なし、作業場面が細切れになる。「えーと」だけの発言が残る |
| 字幕 | 端末内 Whisper base（q8・約80MB）。辞書のバイアスと音声での確認つき用語修正 | 合成音声のテストでは一致率89〜93%だが、実際の撮影では誤変換が多い（ユーザー評価）。モデルが小さいことが根本的な限界 |
| ズーム | 手元が動く2秒以上の場面だけ 1.03〜1.08倍。ON/OFFのみ | ズームアウトがない。頻度・強さを選べない |
| BGM | なし | — |
| ロング動画 | 入力画面のみ（選べない） | 書き出しは出力全体をメモリに持つため、10分（約600MB以上）ではiPhoneで落ちる |

## 開発の順番と方針

各段階は別々にテストし、プルリクエストで確認してから main にマージする（マージはユーザーが行う）。

### 第1段階: 自動カットをより自然に（このPR）

- 声の出始め・消えていく語尾まで含めて検出（大きな音で見つけ、小さな音が続く所まで最大0.3秒/0.45秒広げる）
- Whisper の時刻で声を切り落とさない。声の区間ごと残し、2つの文が続けて話されている所だけ一番静かな点で分ける
- 間の整理: 文の中の0.5秒以下の間はそのまま、長い間は0.42〜0.6秒に縮める（長い間ほど少し長く）。
  話し始めの前0.18秒・話し終わりの後0.32秒を残し、文と文の間は約0.5秒（テンポ重視は約0.36秒）。すべての無音は消さない
- つなぎ目の音: 一度0にせず、40msの等パワー・クロスフェードで入れ替える（部屋の雑音が途切れない）
- 「なので」「そして」で始まる文・「〜て、」で終わる文は、前後の文とまとめて残すか外す（話の前後関係を保つ）
- ハサミの音のような短い音がとびとびに続く区間は声と見なさない（作業場面として残す。ハサミの音がある作業場面は点数を上げる）
- 「えーと」だけの発言は除外
- 評価: 実際の撮影に近い話し方のテスト動画（`tests/e2e/make-ja-natural.py`）を書き出し、
  言葉の欠け・文の途中のカット・間の長さ・つなぎ目の音の落ち込みを `tests/e2e/eval-cuts.py` で測る

### 追加: 途中から再開（v0.8・追加費用0円）

外部サーバーは使わず（無料のバックグラウンド処理は、規約・課金・提供条件の点で現実的な方法がなかった）、
iPhoneの中だけで「Safariを閉じたら一時停止、開き直したら続きから再開」する方式にした。閉じている間は進まない。

- 解析の結果（音声・文字起こしの区間ごと・手元の動きの途中経過）と構成を IndexedDB に保存し、終わった段階を飛ばす
- 書き出しは約8秒ごとの区間に分け、区間ごとのMP4を端末内（OPFS）に保存。書き終えた区間はやり直さない
- 保存した区間の映像を再エンコードせずにつなぎ、音声は通して作る（区間の境目で音が途切れない）
- 書き出し・仕上げともファイルへ少しずつ書くので、10分の動画でも動画全体をメモリに持たない（第5段階の前提）
- 元の動画も端末内にコピーし、選び直さずに再開できる（空きがなければ選び直し）
- 容量の確認・空き不足での一時停止・保存データが消えたときの書き出し直し・警告表示

### 第2段階: 字幕の精度（最重要）

1. 現在の Whisper base の実力を、実際の撮影音声（ユーザーの動画、許可をもらった短い区間）で測る。
   合成音声だけでは実際の誤変換の傾向がわからないため、**ユーザーが手直しした字幕（端末内に保存済み）を正解として**
   誤りの種類（漢字・助詞・語尾・専門用語・追加された言葉・くり返し）を数える仕組みを入れる
2. 認識エンジンの比較（実装前に表で提示し、ユーザーの許可を得てから導入）

   | 候補 | 方式 | 費用 | 外部送信 |
   | --- | --- | --- | --- |
   | Whisper base（現在） | 端末内（WASM） | 無料 | なし |
   | Whisper small / large-v3-turbo、kotoba-whisper（日本語特化） | 端末内（WebGPU）。メモリ・速度をiPhoneで要検証 | 無料 | なし（初回にモデルをダウンロード） |
   | クラウドの文字起こしAPI（OpenAI・Google・AmiVoice など） | 音声だけを送信 | 有料（1分あたり数円程度の見込み。要確認） | **あり**（音声のみ。ユーザーの許可が必要） |

   それぞれ ①日本語の精度 ②美容用語 ③iPhoneでの安定性 ④1分・15分の処理時間 ⑤1本あたりの費用 ⑥プライバシー を比較する。
   **有料APIの導入・音声の外部送信は、比較結果を見てユーザーが決めるまで行わない**
3. 字幕の改善: 単語ごとの時刻で声と合わせる、文の途中で切れない区切り、話していない言葉（幻聴）の除去、同じ説明のくり返しの除去
4. 字幕の修正画面を改善: 誤変換した単語をまとめて置き換え（「カネル→パネル」を全体に）、よく直す言葉を辞書に覚える

### 第3段階: BGM（著作権の条件を確認できる音源だけ）

- ユーザーが iPhone の「ファイル」から音源を選ぶ（YouTube オーディオライブラリ等でダウンロードした、利用条件を確認済みのもの）
- 読み込むときに「入手元・ライセンス・クレジット表記の要否」を確認するチェックを必須にし、確認できない音源は警告して自動では使わない
- 初期音量2%・0〜5%で0.5%刻み。音源ごとの音量差をなくすため、音源の平均音量（ラウドネス）をそろえてから%を掛ける
- 話している間は自動でさらに下げる（ダッキング）。最初と最後はフェード。短い曲は継ぎ目でクロスフェードしてループ
- 「声に対する聞こえ方」を確認できるよう、確認画面で声＋BGMの試聴（10秒）を再生できるようにする
- BGMなしでも従来どおり書き出せることをテストで確認する

### 第4段階: 自然なズームイン・ズームアウト

- 重要な場面（用語・必ず残す場面・手元の動き）でゆっくりズームイン、場面の切り替えや説明の区切りでズームアウト
- 同じ構図が長く続くときだけ変化をつける。倍率は1.03〜1.10倍、変化は2秒以上かけて、間隔をあける
- ズームの頻度（少なめ・ふつう・多め）と強さ（控えめ・ふつう）を編集前に選べるようにする
- 手元・ハサミの範囲が枠から出ない場合だけズーム。色や質感の加工はしない

### 第5段階: ロング動画（横16:9・約10分）

- 10〜15分の素材で問題になるのはメモリ。v0.7 までは書き出した動画全体（10分で約600MB以上）をメモリに持っていた
  → v0.8 で、区間ごとにファイルへ書き出してつなぐ方式に変更済み（残りは横16:9の画面構成・字幕の配置・長い動画の場面選び）
- 方針（iPhone内で処理）:
  - 書き出しは、端末内のファイル領域（OPFS）に少しずつ書く（メモリには数MBしか持たない）。保存も同じファイルから行う
  - 解析は音声・動き・文字起こしを数分ごとに区切り、区切りごとにメモリを解放する
  - 文字起こしは数分ごとに進み具合を保存し、途中でページが落ちても続きから再開できるようにする
- iPhone実機で安定しない場合に備えて、クラウドでの処理（動画をアップロードしてサーバーで編集）も比較する。
  費用・アップロード時間・プライバシーを示し、ユーザーの判断を待つ
- 1920×1080・H.264/AAC・ビットレートは画質と容量のバランスで決める（約8Mbps・10分で約600MB）

### 第6段階: iPhone実機での総合テスト

- 実機テストの手順書（撮影〜保存までのチェックリスト）と、診断情報で測る項目（処理時間・メモリ・落ちた段階）を整備
- ショート・ロングそれぞれで、手直しにかかった箇所の数を記録して品質を評価する

## テスト環境の制約（この開発環境）

- Whisper のモデル（Hugging Face）と Chrome for Testing の配布元にはネットワークの設定で接続できないため、
  通しテストは Playwright 同梱の Chromium（H.264 の読み書き可）と偽の文字起こし（正解の文を少しずらした時刻で返す）で行っている
- 本物の Whisper での確認には、環境のネットワーク設定で `huggingface.co` を許可する必要がある
- 処理時間・メモリはパソコンでの測定値。iPhone 実機では異なる（第6段階で実機の値を記録する）
