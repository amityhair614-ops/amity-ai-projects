# 改善版（v2）: 字幕の正確さと自然なカット（テスト環境だけ）

テスト環境 **`/test/`** で開いたときだけ動く。今の公開ページ（`/`）と main は変えていない。
`/test/?v2=0` で開くと、今までの方式（同じテスト環境の表示のまま）になり、同じ素材で比べられる。

## 何を変えたか

### 1. 音声認識（`js/plan.js` の `shortAsrWindows`・`voiceGapWindows`・`mergeAsrPasses`、`js/verify.js`）

| | 今まで | v2 |
|---|---|---|
| 読み方 | 30秒ごとの窓（A）＋話のまとまりごとの窓（C）。文字の少ない所は15秒ずらした窓（B） | **0.3秒以上の間で区切った短い窓（8秒まで）**（A）＋話のまとまりごとの窓（C） |
| 言葉の途中で区切らない | — | 0.3秒未満の間では区切らない。1.5秒未満の短い声は、となりとつなぐ。窓の切れ目が話の途中（間が0.5秒未満）なら、そこで A と C の字が違うときは C を使う |
| 合わせ方 | A を基に、B・C で落とした言葉を補う | 短い窓（A）を基に、C で落とした言葉を補う。時刻は A のまま。同じ言葉が時刻のずれで2回入らないようにする |
| 読み直し | 文字が1つもない声（1秒以上） | **文字と文字の間が1.2秒以上あいていて、そこに声がある所**も、その声だけで読み直す（間に入れるだけ） |
| 音声での確かめ | 別の読み方の結果を、音声の点数で選ぶ | 同じ。ただし、**2文字以上を消す直しはしない**（長い音声の点数は消す方に偏るため）。A と C の言葉の違い（「修正過程」「修正カット」）は、音声がはっきり逆でなければ C（前後の話の流れで読んだ方）にして要確認の印を付ける。「〜ていきま」で切れた語尾の「す」を音声で確かめて補う。漢字の言葉を別の用語に置き換えるのは、音声がはっきり合うときだけ |

文字数の多い結果を、そのまま選ぶことはしていない（違う所は、音声の点数で選ぶ）。

### 2. カット（`PACES.manual`・`quietEdges`・`bridgeSelected`）

- 0.35秒以下の間は削らない。長い間も0.25〜0.4秒は残す（手動編集に近いテンポ）
- 小さな声の語尾（最大0.6秒）・話し始め（最大0.3秒）を残す
- 選んだ場面と場面の間に声があれば、間も残す（話している途中で切らない）
- 「うん」: 字幕AIの「軽く」の時刻が「うん」の上にずれていたのを直した（短い窓の時刻を使う）。文字にならない短い声は、今までどおり外す

### 3. 字幕（`setSubtitleMode('sentence')`・`setAsSpoken`）

- **1文を1枚**（1行15文字・2行まで。26文字を超える文・はっきりした文の終わりで分ける）
- 話したとおりに出す。省くのは、つなぎ言葉（えー・あの・うーん）と、調子をとる「ね」だけ
  （今までは「このように」「それから」「あと」なども省いていた。手動編集の字幕は残していた）
- **聞き間違えた用語の直し**: 完成後の修正の指示に「「セルフカト」を「セルフカット」に直す」（または「セルフカト→セルフカット」）と書くと、
  動画全体の字幕の同じ言葉を置き換える（1文字ごとの時刻も合わせる）

## 残っている課題

- 1106「軽くする際」→「軽くするサイン」: 短い窓・長い窓のどちらも「サイン」と読む（今までは30秒の窓が「際」と読めた）
- 1111「ヘアカッター」→「部屋肩」: 短い窓・長い窓のどちらも「部屋肩」と読む（今までは30秒の窓が読めた）
- 文の区切りの誤り: 語尾を落とした所（「落ちていきま」）で文が分かれず、次の文の頭が前の字幕に付く
- 表示のタイミング: 読み直した声（間に入れた文字）の時刻が、実際の声より0.3〜0.5秒早いことがある
- iPhone の Safari では、まだ試していない（処理時間は短い窓の数だけ増える。1112: 解析 44秒、今まで 66秒〔iPhone で作った版〕）
