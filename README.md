# Amity AI動画編集

iPhoneだけで使える、自分専用のYouTube動画編集ツールです。
美容師のカット解説動画から、**約60秒・縦9:16・日本語字幕付きのYouTubeショート**を自動で作ります。

## しくみ

GitHub Pages は「ファイルを置くだけ」のサーバーなので、編集処理はすべて **iPhoneのSafariの中** で行います。
動画はどこにも送信されず、追加のクラウド契約や費用はかかりません。

| 処理 | 方法 | 状態 |
| --- | --- | --- |
| 動画の読み込み | [Mediabunny](https://mediabunny.dev/)（`vendor/`）で、ファイルの必要な部分だけを読む | パソコンで確認 |
| 無音・長い間のカット | 音量（50msごと）から声の区間を検出。弱い語尾まで残し、長い間は自然な長さ（約0.4〜0.6秒）に縮める。つなぎ目は音をなめらかに入れ替える | パソコンで確認（v0.7） |
| 言い直しの検出 | 文字起こし結果で、似た発言のくり返し・「言い直します」等を検出 | 簡易版 |
| 重要な場面を残す | 手元の動きの量（約1秒ごとのコマの差）＋美容用語で点数をつける | 簡易版 |
| 約60秒・9:16 | 点数の高い場面を時系列で並べ、動きのある位置で縦に切り抜く | パソコンで確認 |
| 日本語字幕 | 端末内のWhisper（[Transformers.js](https://huggingface.co/docs/transformers.js)）。美容用語の辞書と、音声で確かめてから直す用語修正 | パソコンで確認（既定はOFF。失敗しても字幕なしで続行） |
| 字幕のタイミング | Whisper の時刻を、細かい発話検出で声の出始め・終わりに合わせ、カット後の時刻に変換 | パソコンで確認 |
| 字幕の手直し | 文字の修正・表示の開始/終了を0.1秒ずつ・全体のずらし・その部分の音声を再生。自動保存してMP4に反映 | パソコンで確認 |
| 字幕のデザイン | 白のゴシック体・最大2行・薄い影・フェード。手元に重ならない上/下に配置。言葉の途中で改行しない | パソコンで確認（書き出し時にON/OFF） |
| 自然なズーム | 手元がまとまって動く2秒以上の場面だけ、ゆっくり1.03〜1.08倍。10秒以上あけ、手元が切れる場合はしない | パソコンで確認（書き出し時にON/OFF） |
| MP4書き出し・保存 | WebCodecs（H.264/AAC）で1080×1920のMP4を作り、共有メニューから写真に保存。約8秒ごとの区間に分けて端末内に保存しながら書き出す | パソコンで確認 |
| 途中から再開 | Safariを閉じると一時停止。もう一度開くと、保存してある解析結果・書き終えた区間を使って続きから再開 | パソコンで確認（v0.8） |

「パソコンで確認」= パソコン上のChromeでのテストで動作確認済み。**iPhone実機では v0.3 の修正後まだ確認していません。**
iOS 26 以降の Safari が必要です。

## メモリを抑える工夫（v0.3）

iPhone の Safari はメモリが足りなくなると、エラーを出さずにページを再読み込みします（v0.2 で4K縦動画の処理中に発生）。

- ファイルは一部ずつ読む（`BlobSource` の stream reader を使わない。キャッシュ 8MB）
- 映像は自前の `VideoDecoder` で1コマずつ展開してすぐ閉じる。先読みは数コマまで
- コマは「切り抜き＋縮小」だけで canvas に描き、回転は描いた後の画像に対して行う
  （変換をかけた canvas に動画のコマを直接描くと、コマのメモリが解放されず増え続けることがあった）
- 動きの解析は 96×54 に縮小した画像で行い、書き出しは 1080×1920 固定
- 音声は少しずつ読み、文字起こし用の 16kHz モノラルだけを残す。文字起こしが終わったら手放す
- 処理中は `<video>` 要素から動画を外す
- 音声を WebCodecs で読めない場合は、区間ごとに小さな M4A に詰め直して Web Audio で読む

4K縦MOV（188MB・1分02秒）でのページのメモリのピーク（パソコンの Chrome で測定、GPU有効）:

| 段階 | v0.2 | v0.3 |
| --- | --- | --- |
| 音声の読み込み | 559MB | 265MB |
| 動きの解析 | 572MB | 391MB |
| 書き出し | 783MB | 560MB |

## 字幕AIの安定化（v0.4）

v0.3 までは字幕AIを実物で動かせていませんでした。v0.4 では Whisper（whisper-base・q8）を実際に動かして、次の問題を直しました。

- **メモリ**: 単語単位の時刻用の「注意の重み」を出力する形式のモデルだと、文字起こし中のページが約1.9GBに達した。
  出力しない形式（アプリが使う公式の onnx-community 版はこちらの形式のはず）では約0.9〜1.0GB。
  どちらの形式を読み込んだかを診断情報に記録する。重い「高精度（small）」は削除した
- **専門用語**: 「パネル→カネル」「毛先→下先」「量感→ローカー」などの誤りが多かった（文字の一致率 68%）。
  美容用語を並べたプロンプトを先に与え、よくある聞き間違いを補正して 81% に改善
- **文の区切り**: プロンプトを与えると Whisper が文ごとの時刻を出さなくなるため、
  「。」で文に分け、無音の切れ目（長い間ほど優先）に合わせて時刻を割り当てる
- **言い直し**: ひらがな表記（「いい直します」等）でも合図として検出。合図の前に内容がある文は、その文だけを除外
- 文字起こしが長引いたときに「字幕をスキップして続ける」ボタンで先に進める

## 字幕の精度とタイミング（v0.5）

| 項目 | v0.4 | v0.5 |
| --- | --- | --- |
| 話した内容との一致率（静かな環境） | 85.2% | 92.6% |
| 話した内容との一致率（サロンの雑音・やや早口） | — | 89.3% |
| 字幕の出始めと声の出始めの差（中央値 / 最大） | 0.33s / 16.6s | 0.02s / 0.77s |
| 字幕の終わりと話し終わりの差（中央値 / 最大） | — | 0.01〜0.04s / 0.06s |

（パソコンの Chrome、日本語の合成音声による美容解説のテスト動画 `tests/e2e/make-ja-beauty.py` で測定）

- **字幕のズレの原因**: v0.4 で精度のために与えていたプロンプトのせいで、Whisper が文ごとの時刻を出さなくなっていた。
  プロンプトをやめ、美容用語を書き始めたら続きを選びやすくする軽いバイアスに変更
- **用語の修正は音声で確かめてから**: 辞書（`BEAUTY_TERMS`）から「エリアシ→襟足」「ハネル→パネル」などの修正案を作り、
  同じ音声に対して元の文と修正案のどちらがもっともらしいかを Whisper に採点させ、基準を満たすものだけ直す。
  同じ読みの書き換えは採用、辞書の書き間違いは対数尤度の差 -6 まで、似たカタカナ語は -3 まで。強制的な置き換えはしない
- **16kHz への変換**: 単純な間引きだと高い音が折り返して雑音になり、聞き取りが悪くなっていた。低域通過フィルターつきに（`js/resample.js`）
- **表示時刻**: Whisper の文の時刻を、細かい発話検出で声の出始め・終わりに合わせる。文の中のページは読みの長さで割り振って息継ぎに合わせる。
  元の動画の時刻からカット後の時刻へは、削った無音を考慮して変換する。自動カットの区切りには使わない
- **手直し**: 構成の確認画面で、字幕の文字・表示の開始/終了（0.1秒単位）・全体のずらしを直せる。
  動画ごとに `localStorage` へ自動保存し、同じ動画をもう一度解析したときも引き継ぐ

## 編集前の入力（v0.6・第1段階）

動画を選んだ後に、次の内容を入力できます。**すべて任意**で、何も入力しなければ従来と同じ自動編集になります（同じ場面が選ばれることをテストで確認）。

| 入力 | 使い方 |
| --- | --- |
| 動画の種類 | ショート（縦9:16・1080×1920）。ロング（横16:9・1920×1080）は第5段階で対応するまで選べません |
| 完成動画の長さ | ショート: 30秒・45秒・60秒・自由入力（10〜180秒）。ロング: 5・8・10・12分・自由入力（準備中） |
| 編集スタイル | シンプル・オシャレ（初期設定）/ テンポ重視（短い場面を選びやすく、ズームの間隔 6秒・最大1.10倍） |
| タイトル・内容・流れ | 取り出した用語（例: ボブ・セニング・45度）を話している場面の点数を上げる |
| 一番伝えたいこと | 同上（重みを大きく） |
| 流れ | 段階の数（3〜8）で動画全体を区切り、各区間から場面を選ぶ。**順番は元の動画のまま** |
| 必ず残したい説明や場面 | 1行に1つ。一番合う発言を「必ず残す」にし、目標時間を超えても削らない。関連する発言と、その直後の作業場面は点数を上げる |

- 入力の言葉は、文字起こしで「書き始めたら続きを選びやすくする」用語にも加えます（強制はしない）。**入力した文が字幕に追加されることはありません**
- 確認画面に「目標 → 完成予定」を表示。収まらないときは理由（必ず残す場面だけで超える／元の動画が短い／素材が足りない／場面の区切り）を表示
- 確認画面で入力を変えたら「変更した入力内容で構成し直す」で、解析し直さずに構成だけ作り直せます
- 種類・長さ・スタイルは次回も引き継ぎ、文章の入力は動画ごとに端末内（`localStorage`）へ保存します

## 自動カットの自然さ（v0.7・第1段階）

「不自然な間が残る」「切る位置がおかしい」の原因を、実際の撮影に近い話し方のテスト動画（`tests/e2e/make-ja-natural.py`：
考えながら話す長い間・弱く消える語尾・息・ハサミの音・えーと・言い直し・「なので」で続く文）で調べて直しました。

| 原因（v0.6） | 直したこと（v0.7） |
| --- | --- |
| 文字起こしの時刻で声を切り落としていた（時刻が早く終わると語尾が欠ける・正確だと文と文の間が0秒になる） | 声の区間ごと残す。2つの文を続けて話している所だけ、境目の一番静かな点で分ける |
| 0.3秒以上の無音は、長さに関係なく約0.2秒に詰めていた | 文の中の0.5秒以下の間はそのまま。長い間は0.42〜0.6秒に（長い間ほど少し長く）。話し始めの前0.18秒・話し終わりの後0.32秒を残す。文と文の間は約0.5秒（テンポ重視は約0.35秒） |
| 小さな音（言葉の出始め・消えていく語尾）を声と見なさなかった | 大きな音で見つけた声を、小さな音が続く所まで広げる（前に最大0.3秒・後ろに最大0.45秒） |
| つなぎ目ごとに音を一度0にしていた（部屋の雑音ごと「プツッ」と途切れる） | 40msのクロスフェードで入れ替える。動画の最初と最後だけ短くフェード |
| ハサミの音を声と見なし、作業場面を細切れにしていた | 短い音がとびとびに続くだけの区間は声にしない。作業場面として残す（ハサミの音がある場面は少し優先） |
| 「えーと」だけの発言が、文字起こしのない声として残っていた | 「つなぎ言葉のみ」として除外 |
| 「なので…」で始まる文だけが残ることがあった | 前の文に続く文・「〜て、」で終わる文は前後とまとめて残すか外す。文字起こしなしでも1.2秒未満の間でつながった声はまとめる |
| — | 話していない作業場面は目標時間の40%まで（説明が削られすぎない）。言い直した後の発言は優先して残す |

書き出したMP4での評価（`tests/e2e/eval-cuts.py`。パソコンの Chromium・文字起こしは正解の文を Whisper のように少しずらした時刻で返す偽のデータ）:

| テスト動画（目標の長さ） | 語尾・頭が欠けた句 v0.6→v0.7 | 文と文の間（中央値） v0.6→v0.7 | 0.25秒未満に詰まった文の間 v0.6→v0.7 | つなぎ目で音が途切れた所 v0.6→v0.7 |
| --- | --- | --- | --- | --- |
| 自然な話し方（45秒） | 2 → 0 | 0.17s → 0.48s | 6 → 0 | 19/27 → 0/15 |
| 自然な話し方・字幕OFF（45秒） | 1 → 0 | 0.14s → 0.48s | 8 → 0 | 19/24 → 0/11 |
| 自然な話し方・テンポ重視（45秒） | 2 → 0 | 0.17s → 0.34s | 6 → 0 | 19/27 → 0/14 |
| 美容解説・静か（60秒） | 3 → 0 | 0.01s → 0.55s | 8 → 0 | 14/16 → 0/16 |
| 美容解説・サロンの雑音（45秒） | 5 → 0 | 0.01s → 0.35s | 6 → 0 | 15/15 → 0/6 |

- 文の途中で切れた文はどれも 0（v0.7 の開発途中に字幕OFFで2件出たため、上の「まとめる」処理を追加）
- 1.2秒より長い間（作業場面をはさむ所を除く）はどれも 0
- 解析・書き出しの時間とメモリは v0.6 と同じ（自然な話し方・45秒: 解析 約6秒・書き出し 約190〜210秒・ページのメモリのピーク 約610〜630MB。パソコンでの値）
- **iPhone実機ではまだ確認していません。** テスト音声は合成音声なので、実際の声で「間」が自然に聞こえるかは実機で確認が必要です

## 途中から再開（v0.8）

追加費用0円・外部サーバーなしで、iPhoneの中だけで処理する方式です。

- **Safariを閉じる・ほかのアプリに切り替える・画面を消すと、編集は一時停止します。閉じている間は進みません**
  （iPhone の Safari は、画面に出ていないページの処理を数秒で止めるため。Webページだけで処理を続ける方法はありません）
- もう一度開くと、画面上部の「途中の編集」に保存してある所までの状態が出ます。「続きから再開」で続きから進めます
- 進み具合の数字だけでなく、**処理した結果そのもの**を端末内に保存し、終わった処理はやり直しません

| 段階 | 保存するもの | 途中で止まったとき |
| --- | --- | --- |
| 元の動画のコピー | 選んだ動画を端末内の保存領域（OPFS）にコピー | 再開時に動画を選び直さなくてよい。空きが足りない・コピーが消えたときは、同じ動画を選び直す（大きさと長さで同じ動画か確かめる） |
| 音声の解析 | 50msごとの音量、文字起こし用の16kHz音声 | この段階は最初からやり直す（1分の動画で数秒） |
| 文字起こし | 約28秒の区間ごとの結果 | 保存済みの区間は飛ばす |
| 手元の動き | 約30秒ぶんごとの途中の結果 | 保存した所から続ける |
| 構成の確認 | 選んだ場面・入力内容（字幕の手直しは従来どおり別に保存） | 同じ構成を表示する |
| 映像の書き出し | **約8秒ごとの区間をMP4ファイルとして保存** | 書き終えた区間はやり直さず、書きかけの1区間だけやり直す |
| 仕上げ | 区間の映像を再エンコードせずにつなぎ、音声を最初から最後まで通して作る | 仕上げだけやり直す（1分の動画で数秒） |

進み具合と解析結果（小さなデータ）は IndexedDB に、大きなデータ（動画のコピー・区間・完成したMP4）は OPFS のファイルに書きます。
OPFS への書き込みは、古い iOS でも使える `createSyncAccessHandle()`（ワーカーの中）を使います（`js/opfs-worker.js`）。
書き出しも仕上げも、ファイルに少しずつ書くので、**動画全体をメモリに持ちません**（v0.7 までは完成した動画をメモリに持っていたため、長い動画ではメモリが足りなくなっていた）。

### 保存に必要な容量と、足りないとき

| 必要なもの | 目安 |
| --- | --- |
| 元の動画のコピー | 元の動画と同じ大きさ（iPhone の4K・1分で約200MB、15分で約1.5〜3GB） |
| 文字起こし用の音声（文字起こしが終わったら消す） | 1分あたり約4MB |
| 書き出した区間＋完成したMP4（完成したら区間は消す） | 完成した動画1分あたり約150MB × 2 |

- 書き出す前に、ブラウザが見積もった残りの容量と比べ、足りなければ書き出しを始めずに必要な量と空きを表示します
- 元の動画をコピーする空きがなければ、コピーせずに進めます（再開するときは動画を選び直す）
- 書き出しの途中で空きがなくなったときは、書き終えた区間を残したまま一時停止し、空きを増やしてから再開できます
- 途中経過を保存できなかったときは、編集は続けたまま、その旨を表示します（途中で止まると最初からになる）

### 保存データが消えることへの備え

保存データは必ず残るとは限りません（iPhone の空き容量不足、Safari の「履歴とWebサイトデータを消去」、長期間使わない場合など）。

- 画面に警告を出し、元の動画は写真アプリに残しておくこと、完成したら早めに保存することを案内します
- 消されにくくするよう、ブラウザに保存の継続（`navigator.storage.persist()`）をお願いします（認められるとは限らない）。ホーム画面に追加して開くと消えにくくなります
- 再開するときは、保存したはずの区間が残っているか確かめ、消えていた区間だけ書き出し直します。完成した動画が消えていたら、構成はそのまま書き出し直せます
- 「保存データを削除」で、作業ごとに保存データを消せます（元の動画は消えません）

### 検証結果（パソコンの Chromium・4コア。ブラウザのプロセスを強制終了して再開）

途中でブラウザを強制終了し（後片付けの処理が一切動かない、Safari が落ちたときに近い止め方）、もう一度開いて「続きから再開」を押した（`tests/e2e/resume.mjs`）。

**1分の動画（1分24秒の素材 → 約43秒）**: 途中で止めずに書き出した場合は、解析 約6〜7秒・書き出し 約142〜151秒・ページのメモリのピーク 約590〜650MB（v0.7 は 約190〜210秒・610〜630MB）

| 止めた所 | 再開したときの動き | 結果 |
| --- | --- | --- |
| 手元の動きの解析（36%） | 音声・文字起こしは保存した結果を使い、動きは36%から続けた | 完成 |
| 文字起こし（3区間中1区間を保存） | 残りの区間だけ文字起こし | 完成 |
| 書き出し（7区間中2区間を保存） | 2区間を再利用し、残り5区間を書き出した | 完成 |
| 書き出しで2回（2区間・4区間を保存した後） | 3回に分けて処理し、2区間・4区間を再利用 | 完成 |
| 仕上げ（区間をつなぐ途中） | 7区間すべてを再利用し、仕上げだけ（3秒） | 完成 |
| 書き出し（3区間を保存）＋元の動画のコピーを削除 | 「同じ動画を選び直してください」と表示 → 選び直すと3区間を再利用 | 完成 |

- どの場合も、完成したMP4は 1278コマ（42.6秒）・音声と映像の長さが一致・デコードのエラーなし

### 技術的な制約

- **閉じている間は処理が進みません**（一時停止と再開。バックグラウンドで続ける方式ではありません）
- 再開のときに、止まった区間（最大約8秒ぶん）と、音声の解析・仕上げは最初からやり直します
- 区間をつなぐには、区間ごとの映像の形式（H.264 の設定）が同じである必要があります。違った場合は、区間に分けずに一度で書き出し直します（その場合は途中から再開できません）。
  パソコンの Chromium では一致しました。iPhone のエンコーダーで一致するかは実機で確認が必要です
- 画面を離れた直後に戻ったとき、エンコーダーが止められていることがあるため、その区間は1回だけ自動でやり直します
- 区間ごとのエンコードのため、区間の境目で画質の変化はほとんどありませんが、区間の始まりは必ずキーフレームになります（ファイルが少し大きくなる程度）
- **iPhone 実機ではまだ確認していません**（OPFS・IndexedDB・共有メニューへの大きなファイルの受け渡し）

## iPhone実機の不具合の修正と、言い直し・くり返しの判断（v0.8.1）

iPhone実機で、v0.8 の書き出しが途中で「EncodingError: Decoder failure」で止まり、「途中の編集」が出ずに再開できなかった。

### 書き出しの失敗（EncodingError: Decoder failure）

iPhone 実機がないため、原因は特定できていない。調べた結果、可能性の高い順に次のとおりで、それぞれに対処した。

| 考えられる原因 | 根拠 | 対処 |
| --- | --- | --- |
| 書き出し中に画面が消えた・ほかのアプリに切り替えた | iOS は画面に出ていないページの映像デコーダーを止める。v0.8 は1回だけすぐにやり直していた（画面が消えたままだと、また失敗する） | 画面を離れたら区間の途中で一時停止し、戻ったらその区間から書き出し直す（失敗にしない） |
| HEVC（iPhone の「高効率」）で、キーフレームより前に表示されるコマ | キーフレームから始めると、前のまとまりを参照するコマは正しくデコードできない。HEVC の open GOP の動画（168コマ該当）で、v0.8 は WebKit で再開後に止まった | そのコマはデコーダーに送らない（表示時刻がキーフレームより前なので、出力には使わない） |
| 区間ごとに作り直す canvas（1080×1920）のメモリ | iPhone では使い終わった canvas のメモリ（GPU）がすぐに解放されない | 書き出し全体で使い回す |
| その他（一時的なデコーダーの失敗） | — | 同じ区間を、作り直したデコーダーで1回、低遅延モードなし・1つ前のキーフレームからでもう1回、やり直す |

失敗したときは、**区間・コマの位置・元の動画の時刻・キーフレーム・送ったコマの数・入力のコーデック・デコーダーの状態・段階（デコード／描画／エンコード／ファイルの読み書き）**を診断情報と保存データに記録する。

調べる途中で、WebKit（Safari と同じエンジン）の音声エンコーダーが、AAC のフレームに同じ時刻を付けて返すことを見つけた（MP4 の音声の時刻が壊れる）。
音声は内蔵の AAC エンコーダー（FFmpeg の WASM 版）で作るようにした。

### 途中から再開できなかった

- **Safari とホーム画面に追加したアプリは、iPhone では保存場所が別**。片方で始めた編集は、もう片方には出ない。画面に、今どちらで開いているかと、同じ方法で開くよう表示した
- 端末内への保存に `createSyncAccessHandle` が使えない環境では、`createWritable`（Safari 26 以降）を使うようにした（WebKitGTK では前者が使えず、v0.8 は保存に失敗していた）
- 保存した作業の控えを localStorage にも残し、保存データを読めないときは「続きから再開できません」と理由（読み込みの失敗・保存の失敗・消えた）を表示する。保存データは勝手に消さない
- 書き出しに失敗しても、書き終えた区間と編集の設定を残し、「途中の編集」から失敗した区間だけやり直せる
- 保存の失敗・読めなかった作業・書き込みの方式（sync / stream）・開いた場所（Safari / ホーム画面）を診断情報に記録する

### 言い直し・くり返しを、話した内容から判断する（`js/content.js`）

| 判断 | 例 | 扱い |
| --- | --- | --- |
| 訂正の合図で始まる文 | 「ここを軽くします。」→「いや、ここじゃなくて、耳後ろを軽くします」 | 前の発言を外し、「いや、ここじゃなくて、」を取り除く |
| 文の途中の訂正 | 「スライスは、一センチ、すみません、二センチの幅で取ります」 | 言い間違えた句と合図だけを取り除き、前の句は残す |
| 同じ説明を続けて2回 | 「パネルを45度に引き出して、カットします」×2 | 前の方を外す（用語がまったく同じときだけ） |
| 文の中のくり返し | 「このパネルを、このパネルを、90度で…」 | 前の「このパネルを、」を取り除く |
| 同じ用語で別の技術 | 「サイドは…45度…」「バックも…45度…」、「0度」と「45度」 | **外さない** |

- 文の一部を取り除くのは、その位置に声の切れ目（0.08秒以上）があるときだけ。なければ文の途中では切らず、候補として表示する
- 文字起こしの間違いを根拠に必要な説明を削らないよう、確かでないもの（あとの文に用語が加わっている・用語が1文字違い・訂正の合図がおわびかもしれない）は外さずに、確認画面に「候補」として出す
- 確認画面で、取り除いた部分は「元に戻す」、候補は「この部分を取り除く」で切り替えられる（選んだ内容は保存され、再開しても残る）

### 字幕の正確さ（最優先）

| 原因（調べて分かったこと） | 直したこと |
| --- | --- |
| 字幕AI（ReazonSpeech）の誤りのほとんどは「言葉を落とす」こと。どこで落とすかは、読む音声の区切り方で大きく変わる（同じ音声で誤り率 3〜35%）。文の途中で区切った窓・長い無音をはさむ窓で落としやすい | 区切り方の違う3通り（30秒ごと／15秒ずらした30秒ごと／0.5秒以上の間で分けたまとまり）で読み、文字の並びを照らし合わせて、どれかが落とした言葉をほかの結果から差し込む（`asrWindows`・`mergeAsrPasses`） |
| 声の区間を0.1秒の間でも分けていたため、続けて話す音声では言葉の途中（「トッ｜プ」）で窓が区切られていた | 0.3秒より短い間では区切らない |
| 読んだ音声の最初の文字の時刻を音声の頭にするため、計算の誤差で文の1文字目が落ちることがあった | 音声の頭の文字も受け取る |
| 同じ読みの別の漢字（根元布巾・痛んで）、ひらがなの1文字違い（つかないで） | 入力した用語・タイトルのひらがな・髪の話でよく間違える漢字（傷む）に合わせて直し、確認の印をつける。「前上がり／前下がり」のような1文字違いは直さない |
| 否定の言葉（しない・ません）を落とすと意味が逆になる | 3通りの聞き取りで否定の言葉・入力した用語の有無が違う文、文の終わりが言葉の途中で終わっている文（「…は軽く」）を **要確認（赤い枠）** にする。確認するまで字幕は完成とみなさず、書き出し前に一覧を出して確かめる |
| 字幕が言葉の途中（「まと／まり」「たくさんで｜きて」「トップ／表面」「アホ毛の／ような」）で分かれる | 「〜して」「〜際に」・言い切りの形（〜ない・〜く）の後・次の文の始まり（それを・この場所）で分ける。声の間は言葉の途中では使わない。読点の1文字は1行の文字数を超えてよい。文の始まりの言葉（あとは）の途中で分かれた文は言葉の前で分ける |
| 原稿の文字の時刻は声より早くなることがある（0.65〜0.77秒早く表示） | 2ページ目からは、近くの声の出始めに合わせる |

### 言い直し・不要な発言

- 文の終わりで言いかけてやめ、次の文で同じ言葉から言い直した部分（「…なのか、トップの」）は、残す最後の文字のすぐ後の声の切れ目で取り除く
- 字幕AIが文字にしなかった声は、確かでないので自動では取り除かず、**取り除ける候補**として確認画面に出す
  （2秒未満の文字にならない声・文の後に続く声・文の途中の言いかけ「…ないと、うまくいきま、うまくカバー…」）

## 字幕AIの聞き間違い・聞き落としを、音声で確かめて直す（v0.9.7）

字幕AI（ReazonSpeech）は、1文字ずつ「いちばん確からしい字」を選んで文字にする。そのため、音が近い言葉の取り違え
（「ボブを」→「部分を」「方を」、「すかない」→「つかない」）や、文の終わりの言い落とし（「結べなくなります」→「結べなく」）が起きる。
v0.9.7 では、文字起こしの後に、**同じモデルで「この音声から、この文字の並びが出てくる確からしさ」を計算し、直す候補と比べる**
（`js/verify.js`。RNN-T の強制アライメント。追加の費用・外部への送信なし。端末の中で計算する）。

- 直す候補は3種類。どれも、元の文字起こしより音声に合っているときだけ使う
  1. 区切り方の違う3通りの読み方の結果（3通りを合わせたときに、言い直しの所で文字が混ざった「うまくいきうません／まくカバー」など）
  2. 入力したタイトル・説明・用語の言葉、美容の用語（「ボブ」など）。**入力した言葉だけを根拠に置き換えることはしない**
     （音声との差が小さいときだけ直す。入力した言葉は話に出やすいので −4.5 まで、美容の用語は −3 まで）
  3. 文の終わりの、聞き落としやすい続き（「〜なく」→「なります」「なる」…、「〜いき」→「ます」「ましょう」…。話し言葉の形から作る）
- 比べるとき、モデルが文字の並びだけで覚えている偏り（よく出る漢字「部分」が有利になる）を半分差し引く
- **確信できない所は直さずに「要確認」**: 音声との差が小さめの直し、否定と肯定の候補が近い文の終わり、
  美容の用語に近いが決めきれない言葉（「つかない」は「すかない」の可能性）は、書き出しの前に赤い枠と確認の表示を出す
- 言葉の途中（「部分」の「部」だけ）・助詞1文字・否定の言葉を消す／足す置き換え・区切りの端（窓の端で音声が切れる所）は、候補にしない
- 言いかけを音で取り除いたときは、1文字ごとの時刻で「取り除いた後の音声」に入る最初の言葉から字幕にする（「ギリギリ」を消さない）
- 入力した言葉に「似ている」だけの置き換え（音声で確かめていないもの）は、音声で確かめた後は行わず、要確認として知らせる

## 数の字幕・聞き分けにくい美容の言葉・読み取れる字幕（v0.9.8）

固定テスト素材 IMG_5992（元の動画 57.90秒・v0.9.7 のAI編集 54.67秒・手動編集 55.67秒。言い間違いがほとんどない動画）で比べた
（`tests/fixtures/img5992`）。

- **数は算用数字**（表示用の字幕だけ。`js/captions.js` の `formatNumbers`）: 数の言葉の後に数える言葉（回・度・cm・mm・分・割…）が
  続くときだけ。続けて数えた所は読点（「1回、2回、3回、4回」）、同じ数をくり返した所は文の切れ目（「4回」／「4回は…」）、
  「二三回」「一から三度」は範囲（「2〜3回」「1〜3度」）。「もう一度」「一度ずつ」「十分」「二度と」は漢字のまま
- 数と数える言葉の間（「いっ…かい」）で文・字幕を分けない（v0.9.7 は「入れていきます一」「回二回三回…」と分かれ、
  画面の「一」が「ー」に見えていた）
- **数の聞き間違いは直さずに要確認**: 前後の数がどれも1けたなのに1つだけ桁がとても大きい数（「1回、2回、3回、4回」の後の
  「123度」。手動編集は「1〜3度」）、読み方によって数の聞き取りが違う所
- **聞き分けにくい美容の言葉の組**（`js/verify.js` の `CONFUSIONS`）: 「ハサミ」と「すきバサミ」、「切る」と「すく」（切らない／すかない・
  切って／すいて）、「短く」と「軽く」。どちらも話に出る言葉なので、音声の方がはっきり合うときだけ入れ替え、近いときは要確認。
  「〜ない」の後の「で」（「すかない」→「すかないで」）、カタカナの言葉の最後の「ー」（「ベタ」→「ベター」）も音声で確かめる
- 長さで分けた確かめる単位は、となりの声を文脈として窓に入れる（端の言葉の点数が乱れないように）
- **読み取れる表示時間**: 文字数に合わせた目安（0.3秒＋1文字0.08秒、最低0.8秒）より短い字幕は、前のすき間から少し早く出し、
  次の字幕への切り替えを少し遅らせる（声とのずれは0.3秒まで）。場面の最後で切れる字幕は、次の場面の字幕が出るまで続けて出す
- 「〜か／もしれない」で字幕を分けない。ページの終わりの調子をとる「ね」（「1〜3度ぐらいね」）は書かない

## 複数の動画を1本に・BGM・言い直しとくり返しの見直し（v0.9.9）

- **複数の動画（3本まで）を1本の完成動画に**（`js/sources.js`）
  - 「動画を選択」で2〜3本をまとめて選ぶか、「＋ 動画を追加」で足す。一覧で並べ替え（▲▼）・外す（✕）ができる
  - 動画ごとに音声・手元の動きを1本ずつ解析し（メモリには1本ずつ読む）、間に1秒の無音をはさんだ「つないだ時刻」に並べる。
    カット・字幕・冒頭のテキスト・最後のフェードは、今までと同じ計算をそのまま使う
  - 動画と動画の間の無音は、ほかの長い間と同じく切られる。つなぎ目は場面の前後の余白（0.3秒ほど）だけでつながる
  - 書き出すときだけ、つないだ時刻を「何本目の動画の何秒」に戻して読む（向きが違う動画・解像度が違う動画にも対応。
    縦横の向き・比率が違う動画はまとめない）
  - 途中から再開: 元の動画のコピーを本数分保存する（source・source-1・source-2）。消えていたら、同じ動画を同じ順番で選び直す
- **BGM**（選んだときだけ）: 使う人が用意した曲（MP3・AAC・WAV）を選ぶ。著作権を確認できない曲をアプリが足すことはしない
  - 初期の音量は2%（0〜10%・0.5%きざみ）。話している間はさらに半分に下げ、冒頭1.5秒でフェードイン、最後2秒でフェードアウト
  - 曲は少しずつ読み（全体をメモリに置かない）、動画より短ければ最初に戻って続ける。途中から再開しても同じ曲を使う
- **くり返しの判断**: あとの発言の方が短いとき（「すき量15%のものを使ってください」…「15%のものを使ってください」）は、
  言い直しではなく念を押すまとめ。前の、くわしい説明を外さない
- **字幕**: 「あと価格は…」の「あと」、答えの「それは」（「それはすき量です」→「すき量です」）、「あまりね」の「ね」は字幕に書かない
  （否定のある文・指す物が要る所は省かない）。「〜で／はなく」「数と円（2000／円）」「問いかけの言葉の前」で区切りを直した
- **用語**: すき量（「好き料」は聞き間違い）。数は「円」「万円」も算用数字

## 字幕はポイントだけ・やわらかいBGM・短い言葉を切らない（v1.0 候補）

固定テスト素材 IMG_6183（元の動画 61.67秒・v0.9.9 のAI編集 58.37秒・手動編集 57.37秒。`tests/fixtures/img6183`）で比べた。

- **言葉の頭を切らない**: 声の区間は短すぎる声を含まないため、「次、左を切った」の「次」（0.2秒）が音声から切り取られ、
  字幕にだけ残っていた。字幕AIがその言葉の文字を出しているときは、その時刻の細かい声の区間を文の声に加える
- **字幕はポイントだけ**（音声はそのまま）: 「このように」「それは」「そうならないために」「しかも」「その」「あの」を、
  意味が変わらない所では字幕に書かない（「その後」「そのまま」「それはどこ」のように意味が変わる所・否定・条件は残す）。
  「そうならないために」だけのページは字幕を出さない（字幕のない時間があってよい）。「〜てです」の「です」も書かない
- **やわらかいBGM**: 曲の高い音を抑え（4kHz より上をなだらかに下げる）、ドラムのような急に大きくなる音を曲の平均の2倍までに
  抑える。話している間は40%に下げ、冒頭2秒・最後2.5秒でなめらかにフェードする。曲を選んだときに、打つ音・高い音が多い
  にぎやかな曲なら「やさしいピアノや静かなアンビエントの曲がおすすめ」と知らせる（曲を変えることはしない）

## 字幕はキリの良い所で止める・声に合わせて切り替える（v1.0 候補・2）

固定テスト素材 IMG_6289（元の動画 48.83秒・AI編集 44.27秒・手動編集 44.60秒。`tests/fixtures/img6289`）で比べた。

- **キリの良い所で止める**: 送り仮名・活用の途中（「伸／ばして」）では切らない。動詞の後の「際」「時」（「軽くしていく際／今後…」）は
  漢字が続いても意味のまとまりの終わり。言い切り（〜ない・〜ます・〜です）の後の息継ぎも文の境目として扱う
  （「とにかく落ち着かない／まとまりが…」）。1ページの目安は8文字（文字数いっぱいまで詰めない）
- **字幕に書かない言葉**（意味が変わらない所だけ。音声は残す）: 文の頭の「あと」「それは」「特に」「もし」（後ろに「〜と」「〜ば」
  「〜なら」などの条件が残るときだけ）「それが」「それを」「そして」「それから」「しかも」「そうならないために」「あの」、文の中の
  「このように」「（〜が）ね」。字幕に分ける前に、その言葉の時刻も一緒に外すので、省いた言葉を話している間は次の字幕を出さない
- **声に合わせる**: 文の途中の字幕の切り替えは、そのページの最初の言葉を話し始めた時刻（直前の声の出始め、なければ字幕AIの文字の
  時刻の0.1秒前）にする。v1.0 候補は、先の声の出始めまで待ったため、声より0.5秒ほど遅れることがあった
- **語尾を切らない**: 文の終わりのすぐ後（0.35秒以内）の短い声（0.5秒以下）は、字幕AIが聞き落とした語尾のことが多いので残す

## 1本でも複数本でも同じ字幕に・字幕AIの3通りの合わせ方の見直し（v1.0 候補・3）

同じ動画（IMG_6289）を1本で編集すると44.69秒、2本に分けて編集すると43.56秒になった。原因と直し方:

- **原因**: 字幕AIは30秒ごとの窓（A・B）と話のまとまりごとの窓（C）の3通りで読み、落とした言葉をほかの結果で補う。
  2本のときは、窓が動画と動画の間の無音をまたいでいたため、B は約18秒ぶんの言葉をまとめて落とし、A は「落ち着かない」の途中で
  窓が切れて「それがとにかく落ち着かない」を落とし、次の窓の頭に「そ」だけを出した。補うときに C の「それが…ない」を、時刻を見ずに
  A のその「そ」の後ろに差し込んだため、13文字の時刻が0.24秒の間に押しつぶされた。その結果、その発言の声（約2.4秒）に文字が無く、
  「文字にならなかった短い声」として外された（1.1秒の差のほとんど）
- **窓を動画ごとに作る**: 動画と動画の間をまたいで読まない（1本で読んだときの読み方に近づける）
- **時刻も見て合わせる**: 読み方ごとの時刻のずれ（最大0.8秒ほど）をそろえてから、時刻の離れた文字（1.5秒以上）は同じ言葉として
  対応させない。差し込んだ文字は聞き取った時刻のまま。話の途中で切れた窓の端（0.3秒以内）の文字が、ほかの読み方の続けて
  読んだ所と食い違うときは、言葉の切れ端の誤りとして使わない。まとまりの区切りは、どの読み方の文字も無い所にする
  （同じ言葉が前後に分かれて2回入らない）
- **聞き取りの確かめ**: 1つの読み方だけが3文字以上を落としたとき、ほかの読み方がその言葉を聞き取っていれば消さない
- 結果: 「悪くなっちゃいそ」→「悪くなっちゃいます」（B の結果を正しい時刻で補えた）、「それはどこなるのか」→「どこなのか」
  （音声で確かめて直す）。過去の素材でも「アホ毛」「結べなく」「ボブをね」「入れていきます」「ぐらいね入れていくように」が
  正しくつながるようになった
- **両方を話した可能性**: 読み方によって違う、共通の文字が無い短い言葉（「では」と「どう」）は、両方を話した並びも音声で確かめる
  （IMG_5992「ではどうやって」。手動編集と同じ）。カタカナ語の最後の「ー」は、直すほどの差がなくても要確認にする
- **書き出したMP4（BGM 2%）**: 1本 44.69秒・2本 45.23秒（前は 43.56秒）。11の発言はどちらも全部使われ、字幕24枚の文字も同じ
  （違いは「どこなるのか／どこなのか」「中の方／中のほう」だけ）。残りの0.5秒の差は、窓の区切りの違いで1文字ごとの時刻が少し変わり、
  間の詰め方が数か所で0.1〜0.2秒ずつ違うため
- **字幕の区切り**: ページの中に、はっきりした切れ目（息継ぎのある「〜なのか／」など）をはさまない。「細かな／短い髪」のように
  「〜な」で後ろの言葉を説明している所では切らない（IMG_5992 91→95%・IMG_5980 85→90%。ほかの素材は下がらない）

## 複数の動画を1本ずつ解析してつなぐ・色を変えない・速くする（v1.0 候補・4）

iPhone の実機テスト（固定テスト素材 `tests/fixtures/img1106`: 3本 25.40＋17.90＋36.17秒・AI編集 61.00秒・手動編集 56.17秒）で、
3本をつないだ自動編集の色・カット・字幕が大きく崩れた。処理の単位ごとに原因を調べて直した。

- **処理の構造**: 今までは3本を「1本の長い動画」としてつないでから、音量・声の区間・文字起こしをまとめて行っていた。
  字幕AIの窓が動画の切れ目をまたぎ、窓の時刻のずれの見積もりが狂って、3本目の最初の文（約5秒）が別の文の中に混ざり、
  そこへ用語の直しで「もみあげ」が入った（「そのようならないためにもみあげまいます」）。
  今は **1本ずつ**、音声の読み込み・声の区間（声の大きさも動画ごと）・言いかけの検出・文字起こし・音声での確かめを行い、
  結果を端末内に保存する（動画の名前・大きさ・長さと、入力した言葉ごと）。つなぐときは時刻をずらして並べるだけで、
  つないだ音声は読まない。並べ替え・追加・作り直しのときは、保存した結果を使い回す。本数の上限は20本（合計15分を超えると注意を出す）
- **色**: 原因は2つ。(1) 書き出す動画の色の印が sRGB になっていた（canvas から書き出すため）。iPhone はそれを BT.709 に
  変換し直して表示するので、暗く・色が薄くなった（2本目・3本目: 背景が約10暗く、彩度が約0.9倍。計算で再現した）。
  元の動画と同じ BT.709 の印にした（値はそのまま）。(2) 1本目は HDR（HLG）で撮影されていて、Safari は HDR のコマを
  変換せずに canvas に描くため、白っぽく・薄くなった（彩度が約0.7倍）。HDR の素材だけ、描いた後に WebGL で SDR に変換する
  （明るさは iPhone が SDR に書き出したコマと比べて決めた。ブラウザが自分で変換するときは、描いた結果を元の値と比べて二重に変換しない）
- **字幕AIの速さ**: 今までは、動画ごと・文字起こしと確かめごとに、字幕AIのモデル（約160MB）を読み込み直していた（3本で6回）。
  1回だけ読み込んで使い回す。区切り方の違う3通りで読むのは変えない（2通りに減らすと約3分の2の時間になったが、
  固定テスト素材で文がまるごと消えた〔IMG_6052「すき量15%のものを使ってください」2か所〕・語尾を落とした〔IMG_6289〕）
- **聞き取りの直しの安全策**: 音の違う用語への置き換えをしない（「起こってし」→「もみあげ」）。前後の文字を含めるともうその用語に
  なっている所は直さない（「セルフカットで｜すきばさみ」の「きばさみ」→「すきバサミ」で「セルフカットです」になった）。
  漢字の言葉とカタカナの言葉の置き換えは要確認にする（「する際｜根元」→「サイン｜根元」）。1つの読み方が聞き落としただけの言葉は消さない
- **字幕**: ページの頭が文の途中なら「それを」などを省かない（「必ず｜それを守ってください」）。「これによって」の前で区切る。
  「すぎばさみ」「杉バサミ」は「すきバサミ」
- **処理時間**: 段階ごとの時間を記録し、完成の画面と診断情報に出す（iPhone での実際の速さを確かめるため）

## カットの強さ・字幕の残り・処理時間の内訳（v1.0 候補・5）

- **カットの強さ**（入力画面）: 「標準」（今までどおり）と「テンポ重視」。テンポ重視は、細かい声の区間の端から頭 0.08秒・語尾 0.13秒
  だけ残す（手動編集9本の余白の中央くらい。標準は頭 約0.15秒・語尾 約0.25秒）。標準で使った声のコマは、テンポ重視でも
  1コマも切らないことを固定テスト素材9本で確かめる（`tests/cut-strength.test.mjs`）。1106 の手動編集は、他の8本より詰めていて
  （声の区間の端から頭 0秒・語尾 0秒、最大0.13秒は語尾の小さな音まで切る）、そこまでは詰めない
- **字幕の残り**: 「たくさんできてき」は、3通りの読み方のうち2つが文をまるごと落とし、残る1つも「ます」を文字にしなかった。
  音声で確かめた「ます」の点数（-1.3）は直す決まり（1.5）に届かないので、直さずに要確認にする（「できてき」→「できてきます」の
  可能性）。「やってしまうと」（0.42秒）は場面の最初の字幕で、前の場面の字幕が消えた後の間に最大0.3秒早く出し、次のページからも
  少し分けてもらう（0.86秒）。「でも」は、手動編集でも省いた動画（1106）と残した動画（5953）があり、どちらも話の向きを変える
  「でも」なので、意味を保つため省かない
- **処理時間**: 完成の画面に、段階ごと（動画の保存・音声・文字起こし〔モデルの準備・音声での確かめ〕・手元の動き・構成・字幕・
  書き出し・仕上げ）と、動画を選んでから完成までの時間（処理の待ち・操作など）を出す。途中から再開しても前回までの時間を足す
- **文字起こしの方式の比較**（固定テスト素材）: 3通り（今の方式）／2通り（約3分の2の時間・IMG_6052 で2文が消えた）／
  2通り＋文字の少ない所だけ3通り目（約8割の時間・IMG_6289 の「悪くなっちゃいます」が「悪くなっちゃいそ」に戻った）。
  精度が下がるため、3通りのままにする

## 完成後の修正の指示・変わっていない区間の再利用・カットと字幕の残り（v1.0 候補・6）

- **完成後の修正の指示**（完成の画面の「修正の指示」）: 完成動画を止めると、その時刻が入る（±0.1秒で手直しもできる）。
  種類は「字幕の文字を直す」「字幕の時刻をずらす」「範囲をカット」「不要な間を詰める」「自由入力」。一覧で編集・削除でき、
  「まとめて適用」で構成だけを作り直す（文字起こし・カットの解析はやり直さない。固定テスト素材で 0.04秒）。適用の前後は、
  元の動画をその場でつないで再生するプレビューで確かめられる（MP4 は作らない）。「元に戻す」で最後に適用した分を取り消せる。
  指示は端末内に保存し、途中でやめても続きから使える。最後に「修正を反映して書き出す」で MP4 を1回だけ作り直す
  - 指示は、完成動画の時刻ではなく元の動画の時刻で保存する。カットで完成動画の長さが変わっても、ほかの字幕・指示の位置はずれない
  - カットした範囲で話した文字は、字幕からも消える（1文字ごとの時刻を使う）
  - 自由入力は「18秒の字幕を○○に変更」「25〜27秒の言い間違いを削除」「32秒の字幕を0.3秒早く表示」「40秒付近の不要な間を詰める」
    のように読み方が1通りに決まるときだけ、その種類の指示として「この内容で使う」を押してもらう。決まらないとき
    （「ここをもう少しいい感じにして」）は「要確認」にして、勝手に変えない
- **通しテスト（1107 の3本・パソコンの Chromium・本物の ReazonSpeech）**: 完成動画（46.5秒）に5件の指示（字幕の文字・0.2秒早く・
  「伸びてから」をカット・38秒付近の間・読めない自由入力）を入れて適用（0.04秒）→ 書き出し直し。読めない自由入力は要確認のまま
  適用せず、残り4件が MP4 に反映された（カットした所の字幕は消え、後ろの字幕はずれずに追従・44.7秒）。書き出し直しは
  61.5秒（最初の書き出しは 175.6秒）。iPhone 実機では未確認
- **変わっていない区間の再利用**: 書き出しを場面ごとの区間に分け、区間の中身（使う元の動画の範囲・切り抜き・字幕・冒頭のテキスト・
  最後のフェード）が前回と同じ区間は、保存してある区間のファイルをそのまま使う。修正の指示で変わった場面だけ書き出し直す
- **書き出しの不具合の修正**: 場面の最初の字幕を前の場面の終わりから少し早く出す（v1.0 候補・5）とき、早めた部分が書き出しで
  描かれていなかった。次の場面の最初の字幕も探して描くようにした
- **カット（1107 の3本）**: 「伸びてから／それから修正したほうが」の「それから」（前の文の「〜てから」のくり返し）と、
  「見てもらうこれ／この／この選択を」の言いかけの「これ」を取り除くようにした（`js/content.js`。指示語で言いかけて、
  すぐ後に同じ指示語で言い直したとき）。AI編集 47.63秒 → 46.5秒（手動編集 44.47秒。残りの差は主に文の前後の0.1〜0.3秒の余白）
- **字幕の区切り**: 句読点のない字幕AIの文字でも、問いかけの終わり（「〜のか」「〜ですか」）の後と、「そんな・こんな」の前を
  文の境目として扱う（「なぜ修正カットを／やってはいけないのか／やればやるほど」。前は「いけないのかやればやるほど」の13文字）

## 字幕を言葉のまとまりで区切る・編集メモ・テンポ重視を初期設定に（v1.0 候補・7）

- **字幕の区切り方を作り直した**（`js/morph.js`・`plan.js` の `phrasePages`）: 文字数ではなく、言葉のまとまり（文節）で区切る。
  形態素解析（kuromoji.js・辞書は IPAdic。無料・端末の中で動く。辞書約17MBは CDN から1回だけ読み込み、ブラウザに保存）で
  文を文節に分け、文節の切れ目ごとに「区切りの強さ」を決める（文の終わり 9・接続の言葉の前 8・条件や理由の節の終わり
  「〜たら」「〜ば」「〜と」7・「〜際」6.8・「〜は」5・「〜で」「〜に」4.5・「〜が」4・「〜を」3・後ろの名詞の説明 1・打ち消しの前 0）。
  声の間（0.12〜0.5秒）で強さを上げ、ページの長さ（12文字まで・最大15文字）と合わせて、文全体で一番よい区切り方を選ぶ。
  文字数をそろえるために次の言葉をくっつけない・短くても意味のまとまった言葉（「結論」）は1枚・区切りの弱い所では長くても
  無理に分けない（「乾いた状態の髪を切ればよいのか」15文字）。句読点のない話し言葉で辞書が取り違えやすい所（「おそれ」を
  「お＋それ」、「かなり」を「か＋なり」、文頭の「でも」を助詞）は直してから使う
  - 1108 のご指定の区切り（9か所）はすべて一致。手動編集の字幕がある過去の固定テスト素材10本で、手動編集の切れ目と同じ所で
    区切った割合の平均は 83.9% → 88.3%（1108 63%→100%・6052 69%→94%・1106 68%→77%。5980 は 90%→70%、5992 95%→91%、
    5830 94%→88%、bob 100%→92% に下がった。いずれも手動編集が15文字を超える1枚にしている所）
  - 辞書を読み込めないとき（通信できない等）は、今までの区切り方で作り、画面で知らせる
- **字幕で省く言葉を、声の時刻ごと取り除く**: 「それとも」「でも」（文の頭）「ちなみに（ですが）」「かなり」（人や物を説明している所。
  「かなり難しいです」のように言い切りにかかる所は残す）「そのような」（後ろに名詞）「〜したいのであれば」の「のであれば」。
  ページの区切りは省く前の文で決め（省く言葉が文の切れ目の手がかりになる）、省いた言葉を話している間は次の字幕を出さない。
  否定・条件（「傷んでなかったら」「〜切るのであれば」）は残す。過去の手動編集で残していた「でも」「そのような」も、ご指定に合わせて省く
- **字幕と声のずれ**: 各ページは、最後の言葉を話し終えた所で消す（次のページまで出し続けない）。読む時間が足りないページを
  声より早く出す・次のページを遅らせる幅を 0.3秒・0.5秒 → 0.15秒・0.3秒に縮めた。1108 で、声より0.15秒以上早く出るページは
  29枚中4枚（最大0.23秒）、声が終わって0.4秒以上残るページは0枚
- **文がまるごと字幕にならなかった**（1108 の6本目「髪の毛はダメージしている場合です」）: 3通りの読み方が同じ11秒の窓で読み、
  3通りとも3.3秒の文を落としていた。どの読み方でも文字にならなかったはっきりした声（1秒以上）は、その声だけをもう一度読む
  （`untranscribedWindows`。1本あたり約1秒）。あわせて、「ダメージ」を打ち消しの「ダメ」と取り違えて要確認にしていたのと、
  文をまるごと落とした読み方と比べて要確認にしていたのを直した
- **編集メモ**（入力画面・動画の一覧）: 全体のメモと、動画1本ごとのメモ。言い間違いは「自動判定・なし・あり」から選ぶ。
  読み方が1通りに決まる書き方だけを使い（`js/memo.js`）、読み取った内容と、読み取れなかった文（反映していない）を画面に出す
  - 「2本目の15秒付近に言い間違いあり」: 取り除ける範囲が見つかっていれば取り除き、なければ確認の印をつける（勝手に範囲を決めて切らない）
  - 「言い間違いなし」: 言い直し・くり返しとして発言を取り除かない。※ 言い直しの探索（音の繰り返し）は72秒の音声で0.02秒しか
    かからないため、省いても速くはならない（時間がかかっているのは文字起こし）
  - 「2本目の10秒付近は削除しないで」「「〜」は残して」: 必ず残す。「字幕では「〜」を省いて」「字幕に「〜」を残して」: 字幕の言葉。
    「「〜」を正確に表示」: 用語（字幕の書き間違いを直す）
  - 完成後の修正の指示（自由入力）でも同じ書き方が使える（「字幕では「かなり」を省いて」→ 動画全体の字幕から省く）
- **カットの強さの初期設定を「テンポ重視」にした**: 手動編集（1107・1108）は、文の前後と文の途中の間を中央0.1秒まで詰めている。
  テンポ重視の話の途中の間を 0.2秒 → 0.12秒にし、初期設定にした（「標準」は「ゆったり」に名前を変えて残す）。標準のまま詰めると、
  前の手動編集（文と文の間 0.3〜0.4秒）の固定テスト素材11件が合わなくなるため、標準は変えていない。1108 は 54.73秒
  （手動編集 52.80秒・前のAI編集 56.67秒。残りの差は主に、手動編集が語尾の小さな音を少し切っている所。語尾は切らない）
- **書き出しの速さ**: キーフレームから使う所までの読み進めのコマ（使わないコマ）を描かないようにした。1コマごとの待ち
  （setTimeout(0)・続けて使うと1回4ミリ秒以上）を、待たされない方法（MessageChannel）にした

## iPhone で「Script error.」・確認がくり返し出る・書き出しが重なる不具合の修正（v1.0 候補・7.1）

- **原因1（Script error.）**: 字幕の辞書（kuromoji）の読み込みで、kuromoji が辞書の URL を `path.join` で作るため
  「https://cdn…」が「https:/cdn…」になっていた。http のページ（パソコンでの確認）では CDN を読みに行くが、https のページ
  （Cloudflare Pages）では同じサイトの `/cdn.jsdelivr.net/…` を読みに行く。辞書の代わりのページが返ると、kuromoji の中で
  例外が起き、別のサイト（CDN）から読み込んだスクリプトの例外なので Safari では「Script error.」としか表示されず、
  辞書の準備も終わらなかった（最大60秒待っていた）。手元の https サーバーで、直す前の版は12個の辞書のファイルをすべて同じサイトに
  読みに行って失敗し、直した版は1.5秒で読み込めることを確かめた（`tests/e2e/morph-https.mjs`・WebKit は `tests/webkit/morph.py`）
  - 修正: kuromoji 本体をアプリと同じ場所（`vendor/kuromoji/`。Apache License 2.0）から読み込み、辞書の読み込み部分を直した
    （URL を直す・ブラウザがすでに解凍したデータはそのまま使う・例外を投げずにエラーを返す）。辞書は今までどおり CDN から。
    読み込めないときは25秒で今までの区切り方に切り替え、同じページでは二度と待たない
- **原因2（確認が何度も出る・書き出しが重なる）**: 「この内容でMP4を書き出す」を押すと、まず辞書の準備を待ってからボタンを止めていた。
  準備に時間がかかる間に何度か押すと、押した回数だけ確認（字幕の要確認・BGM）が順に出て、書き出しも重ねて始まっていた
  - 修正: 押した瞬間にボタンを止め、書き出しは同時に1つだけ（途中から再開・修正の書き出し直しも同じ）。確認事項（字幕の要確認・
    BGM の曲が選ばれていない）は、ポップアップではなく、書き出す前に画面の中にまとめて出し、「このまま書き出す」を押した後は
    書き出しの途中で何も聞かない。BGM の曲を読み込めないときも、聞かずに BGM なしで書き出して知らせる
- **時刻**: 字幕の要確認の時刻は、完成動画の時刻と元の動画の時刻（「元の2本目の0:14」）の両方を出す（前は元の動画をつないだ時刻だけで、
  完成予定の長さより後の時刻に見えていた）
- **エラーの記録**: ページのエラーは、起きたファイル・行と処理の段階を診断情報に記録し、画面にも出す（動画・音声は記録しない）

- `js/jobstore.js` … 途中経過の保存（IndexedDB）と、端末内のファイルの読み書き（OPFS）

- `docs/ROADMAP.md` … 改善計画
