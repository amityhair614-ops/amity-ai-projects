# 今のアプリ（amity-ai-projects・作業ブランチ 9e1c32f 時点）とスキルの方針の対応

コードを読んで照らし合わせたもの。**精度の数字は、これまでの素材（1106〜1112）での結果で、未使用の素材ではまだ測っていない。**

凡例: ○ できている / △ 一部だけ・条件つき / × できていない / 新 新しい処理が必要

## 1. カット

| 方針 | 状況 | 今の実装・分かっていること |
|---|---|---|
| 無駄な間をカット | ○ | 声の区間の間を縮める（`PACES`・`shapePieces`）。v2 は手動編集に近いテンポ（`PACES.manual`）。1112: つないだ所 24→9（手動 10） |
| 言い間違い・言い直しを削除 | △ | 文字の重なり（`content.js` `analyzeContent`）・音の繰り返し（言いかけ）で検出。字幕AIが聞き落とした言い直しは見つけられない。確かでないものは候補として残す |
| 必要な言葉を切らない・語頭語尾 | △ | v2 で小さな語尾を残す（`quietEdges`）・場面の間の声を残す（`bridgeSelected`）。1112: 切りすぎた声 1か所→0。v2 は**テスト環境だけ** |
| 意味のある短い間を残す | △ | 0.35秒以下は残す（v2）。「意味があるか」は判断していない（長さだけ） |
| ハサミの動き・手元の作業を残す | △ | 手元の動き（`motion`）・ハサミの音で、話していない作業の場面を候補にする。どの作業が重要かは判断していない |
| 音声のつなぎ目 | ○ | つなぎ目のクロスフェード（`audiomix.js`） |
| コマの重複・映像の乱れ | ○ | 毎秒30コマの格子・高速書き出しのつなぎ目の確かめ（`fastcut.js` `verifyJoins`）。高速書き出しは「カットのみ」だけ |

## 2. 字幕（言い換え）— 一番大きな差

| 方針 | 状況 | 今の実装・分かっていること |
|---|---|---|
| 重要な内容だけを選ぶ | × | 話したすべての文に字幕を付ける。重要でない場面を字幕なしにする判断はない |
| 短く言い換える | × | **言い換えはしていない。** 今は「言葉を削る」だけ（つなぎ言葉・指示語・「このように」・「なので」などを省く: `captions.js`）。語順を変える・まとめる・「〜してください」→「〜しない」のような書き換えはできない |
| 意味を変えない・情報を足さない | △ | 削るだけなので足すことはない。否定・数の聞き落としは「要確認」の印を付ける（`passDoubts`）。言い換えを入れると、ここの確かめ方を新しく作る必要がある |
| 美容用語を正確に | △ | 美容の用語の一覧（`BEAUTY_TERMS`）・聞き分けにくい言葉の組・入力した言葉で、音声に合うときだけ直す（`verify.js`）。聞き間違いは残る（1112: 「セルフカト」「Uを描く→はなを描く」） |
| 一目で読める・不自然に区切らない | ○ | 1行15文字、言葉のまとまり（形態素）で区切る（`phrasePages`）。v2 は1文1枚（2行まで） |
| 指示語・つなぎ言葉を省く | ○ | 今の公開版は省く。**注意: v2（テスト環境）は「話したとおり」に出すので、このスキルの方針と逆。** 次に v2 を見直すときに合わせる |
| 修正しやすさ | △ | 確認画面で字幕を直せる・完成後の修正の指示（時刻つき）・v2 は「「A」を「B」に直す」で動画全体を置き換え |

**言い換えには、話の意味を理解する処理（言語モデル）が必要。** 文字数の制限・用語の辞書・削る規則では作れない。
- 例「耳の後ろのところが重たくなっているので」→「耳後ろの重さを取る」は、次の動作（軽くする）を前後の文から読み取った言い換えで、文字を削るだけでは出てこない
- 制約: 追加費用なし・動画と音声を外部に送らない・iPhone の Safari だけ。
  有料の API は使えない。端末の中で動く小さな言語モデル（ブラウザで動くもの）は、iPhone のメモリ（音声認識だけで約600MB）・速さ・日本語の言い換えの質が分からない（**未検証**）
- 現実的な案（どれも未検証）:
  1. 端末内の小さな言語モデルで言い換えの候補を作り、人が確認画面で選ぶ・直す
  2. 規則でできる部分（「〜しないようにしてください」→「〜しない」、「〜していきます」→「〜する」など、文の終わりの形の短縮）を先に作り、意味の判断が要る所は候補だけ出す
  3. 重要な文を選ぶ部分（切る位置・角度・注意・否定・数を含む文）を、言葉の手がかりで先に作る
- どの案も、言い換えの「意味が同じか」を確かめる仕組み（否定・数・位置の言葉が消えていないか等）が必要

## 3. 字幕のタイミング

| 方針 | 状況 | 今の実装・分かっていること |
|---|---|---|
| 説明と表示を合わせる | △ | 1文字ごとの時刻で表示（`charPageTimes`・0.1秒前に出す）。1112: 声との差 中央0.2秒、0.3秒を超える文が7〜9文 |
| 手元の動きに合わせる | × | 手元の動きは場面選びにだけ使い、字幕の時刻には使っていない |
| 一瞬で消えない・残り続けない | ○ | 最短0.5秒・文字数に応じた最長（`pageMaxDuration`） |
| 完成動画の画面で確認 | △ | アプリの中では確かめていない。分析プログラム（`subpages.py`）で書き出した動画の字幕のページを見つけられる（文字は目で読む） |

## 4. ショートと長尺

| 方針 | 状況 | 今の実装・分かっていること |
|---|---|---|
| ショート（テンポ優先） | ○ | 目標の長さに合わせて場面を選ぶ（`selectUnits`） |
| 長尺（説明を削りすぎない） | △ | 「カットのみ（試作）」で不要な所だけ削る。長尺での字幕の付け方（重要な場面だけ）は × |

## 5. 完成動画の品質

| 方針 | 状況 | 今の実装・分かっていること |
|---|---|---|
| 色味の維持 | △ | 色の範囲を合わせて書き出す（`color.js`）。高速書き出しは元のコマをそのまま使う。HDR は高速書き出しを使わない |
| 正常に再生できる形式 | △ | PC の Chromium・ffmpeg では確認。iPhone での高速書き出しの再生は未確認 |
| 字幕の誤字・ずれを防ぐ | △ | 要確認の印・書き出す前の確認。字幕AIの聞き間違いは残る |

## 6. 編集時間（目標 5分以内）

- 1112（4本・完成約75秒）: PC で解析44秒＋書き出し278秒（字幕つき）。iPhone で作った版は書き出し333秒
- 字幕つきでは、書き出しだけで5分前後かかる（高速書き出しは「カットのみ」だけ）
- 確認・修正にかかる時間は測っていない。完成後の修正の回数も測っていない
- → 5分以内には、字幕つきの書き出しを速くすること（画質を落とさずに）と、修正の少なさの両方が必要。**未達**

## 新しく必要な処理（まとめ）

1. 新 字幕の言い換え（意味を理解する処理）と、意味が変わっていないかの確かめ
2. 新 重要な文を選び、重要でない場面は字幕なしにする判断
3. 新 手元の動きに合わせた字幕の時刻
4. 新 完成動画の画面での自動の確かめ（字幕の表示時間・重なり・つなぎ目のコマ）
5. 新 字幕つきでも速い書き出し（画質を落とさない）
6. 新 編集時間・修正の回数の測り方（新しい未使用の素材で）
7. 見直し: v2 の「話したとおりの字幕」をこのスキルの方針（言い換え・指示語を省く）に合わせる
